# 分项验证

分别记录结果与实际证据，不以一个“成功”覆盖全部层次：

| 层次 | 证据 |
| --- | --- |
| 定义合法 | 当前开发 definition 的外层结构 validate 结果；契约内容和业务行为另行核验 |
| 发布回读 | 精确应用及指标名的云端当前定义与本次授权变更一致 |
| 运行执行 | 由具有授权的运行身份经 `lovrabet` 实际执行，核对参数、结果、范围和结构；凭证不交接 |
| 业务对账 | 同范围同口径可信明细/权威来源，记录数值及差异；合成案例不证明真实业务正确 |
| 受限身份 | 实际执行主体、应用、允许范围与拒绝条件；管理员通过不能代替 |

案例按真实语义选择：边界时间、退款或状态排除、重复关联/分母、空集/零/null、部分覆盖和权限拒绝。不适用项说明原因，不把订单或结算规则套到所有行业。

涉及精度与聚合时，按主 `rabetbase` 的 `guides/metric-development.md` 核验：BFF/SQL 精确计算到返回表示的链路、精确字符串未被转为普通浮点数、业务舍入时点保持不变。可加指标用同范围权威明细对账，并验证精确中间汇总的等价性；比例/均值核对汇总分子分母，去重数与快照按各自聚合语义验证。页面展示舍入值或分页结果不能作总体对账基准；CLI 校验通过不能代替上述证据。

输出形态以实际契约为准；SQL 数组和 BFF 业务值不强制改成同一对象。定义观察版本或指纹没有执行端绑定证据时只标观察，未知数据截止不标完整，不承诺历史重放。发布改变了既有消费者的参数、单位或口径时，核验迁移影响再交付。

无法取得运行身份或数据时保留该项未验证，可交付已有定义证据，但不能称业务验收完成。执行主体、查询参数、取数时点、覆盖、产物/运行引用按权限留存最小必要信息。
