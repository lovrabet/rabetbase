# 开发与交付流程

## 接受任务

从用户请求和已提供的可信上下文取得业务目标、企业/应用、查询对象、口径及来源、期间/时区、期望例子、已有入口和授权边界。

未知业务规则交负责人确认，权限不足交管理员，缺少数据事实先查询授权范围内的元数据。先复用已有信息，不让用户补 SQL、Schema 或本地目录。普通报告缺数不等于发布授权；来源或范围冲突先核对。

需要澄清业务目标时，优先用宿主实际提供的结构化提问工具（如 question）；没有时用普通对话，不依赖 `/question` 命令。一次问一至两个影响任务的问题：想支持什么决策、关注哪些对象与期间、期望什么结果及完成标准；业务口径未知时再确认统计事件、零分母等规则。已有上下文、口径和授权直接复用。CLI、SQL/BFF、Schema 和结果形态由 Agent 根据真实契约自主选择，不默认让用户决定实现方案。开发任务按需澄清无法自行核实的技术约束，例如必须对接的接口、允许修改的范围、性能要求和验收标准；能从云端契约、授权元数据或已提供仓库查明的事实先自行核实，不设置固定技术问卷。方案影响交付时间、成本、业务范围或完整性时，询问相应取舍；用户明确要求比较技术方案时，说明依据、影响和推荐，不把选型变成所有任务的前置条件。

## 按需准备

明确需要开发指标时才检查工具，复用本次选定的 CLI、随包提供的 skill 和当前开发会话。需要安装而已有授权不覆盖时，先说明安装内容并取得授权，用户拒绝则保留草稿和原报告可完成部分。

- CLI 不存在：核对本机 Node 与官方 `@lovrabet/rabetbase-cli` 目标版本的 engines；按安装授权使用官方 npm 包，未指定版本用 latest，不自行选 beta。安装后核验 CLI 版本，并加载该包提供的 `rabetbase` skill。
- `rabetbase` skill 缺失或与选定的 CLI 包内容不一致时，通过该 CLI 入口执行 `cli-skill install`，再读取配套内容。命令启动或安装失败按真实原因处理，不自动 sudo、换 registry 或反复重装。
- 访问目标应用前，核对连接、开发会话和当前账号在该应用的权限。不复制运行态凭证，也不更换管理员身份绕过拒绝。

安装成功、登录成功、开发权限和发布授权分别判断。“先不发布”包含依赖 SQL/BFF 与指标定义：仅完成本地草稿和可用验证，明确未发布、未真实执行的限制。用户后续授权改变时再继续对应步骤。

## 操作权限核验

权限拒绝时停止受阻操作，返回已完成内容、目标应用/资源、受阻操作、服务端实际拒绝、已知权限要求及未执行动作。未知权限名称由管理员核定，不从岗位推断权限，不默认申请管理员权限，不自行修改权限或借用其他账号。

再次执行前，用当前账号重新核验所需操作权限、当前云端定义和真实依赖；用户声明已获权不能代替实际核验。沿用已确认的目标、应用、期间、口径及适用草稿，契约变化影响原目标时说明差异。两个 CLI 分别认证，开发权限不代表运行执行权限或本次发布授权。

## 能力选择与实施

1. 在目标应用中，用 `rabetbase metric list` 查找候选指标，再用 `rabetbase metric detail --code <code>` 读取当前定义。核对统计口径及所依赖的数据集、SQL 或 BFF 契约。口径一致且满足需求时，复用该指标并交付引用。
2. 确需开发时，按真实事实粒度、关联基数、事件时间、单位、空值和权限形成固定口径。已有共享计算优先复用，不为报表名称另建计算引擎；页面 VO 与指标可复用计算但各自保持契约。
3. 为指标绑定的 ENDPOINT 声明业务请求参数和成功返回数据。格式与示例见 `rabetbase` skill 的 `guides/metric-development.md` 中“编写指标 ENDPOINT 契约”一节。核验入口调用的 SQL 或共享函数。获得对应发布授权后，先发布并回读依赖，再发布并回读入口。结构、权限等范围外改动单列依赖，不扩大当前授权。
4. 新建定义时用 `rabetbase metric example` 取得示例，修改已有指标时从当前云端定义开始编辑。可用临时 JSON 文件，字段要求见 `rabetbase metric schema`。用 `rabetbase metric validate --file <路径>` 校验定义，再用 `rabetbase metric publish --file <路径> --appcode <app> --dry-run` 查看发布差异。核对身份、差异和受影响的调用方，破坏性变更还须确认迁移安排。预演不会锁定或发布指标。取得发布授权后，去掉 `--dry-run` 发布并回读。
5. 写入失败或结果未知时，在原目标应用按指标 code、SQL 编码或 BFF ID 查回本次写入的资源，核对云端内容。已一致的资源跳过，只处理已确认缺失或不一致的资源，沿用原标识。无法确认时报告未知状态和必要诊断，避免重复提交。

## 交付结果

按[验证清单](verification.md)取得证据，用[交付摘要](../templates/statistics-delivery.md)分别列出已通过、失败和未验证。只有定义已发布时才写可消费的云端引用；草稿标记未发布。

返回指标所属应用、稳定指标名、分项验证证据、具体缺口和未执行动作。开发任务不自动授权更新或发送报告、创建订阅。
