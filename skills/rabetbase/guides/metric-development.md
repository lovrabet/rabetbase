# 应用级指标口径与查询开发

开发统计卡片、驾驶舱、报表接口，或让页面与业务 Skill 复用应用级指标时阅读。页面与指标复用计算口径，页面可以保留自己的 VO 接口；指标目录负责发现与口径说明，指标由 BFF 执行，BFF 内可复用 SQL。

明确的指标开发/交付任务使用已安装的 `rabetbase-metrics-generation` 组织需求、分项验证与交付；本指引保持原子开发与发布规则。指标体系按需建设；报告缺数先澄清业务目标并核对已有能力。Agent 自主判断是否需要补齐统计能力，在既有授权内进入开发，不以岗位称呼限制使用，不默认要求用户选择技术路径；开发任务可按需澄清技术约束和验收要求，能自行查明的事实先核实；额外安装、远端写入或发布仍需相应授权。

执行前用 `rabetbase doctor` 核对目标应用、连接与凭证来源。配置存在、会话有效不等于拥有该应用的开发或发布权限；操作权限以服务端校验为准。指标所属应用与业务查询中的客户、门店等对象分开确认，不根据查询对象切换身份。

指标体系以应用为归属和操作边界，按 AppCode 与指标名定位。发布定义仅使其在所属应用生效；页面与业务 Skill 的复用仍需实际授权，不产生平台公共目录或跨应用、跨企业访问权限。

## 1. 确认口径和已有接口

### 执行依据

按以下规则核实业务口径、选择实现方法并验收结果：

| 对象 | 执行规则 |
| --- | --- |
| 查询与聚合 | SQL 运算参考 [ISO/IEC 9075-2](https://www.iso.org/standard/76584.html)，核实目标数据库的类型、NULL 和聚合函数语义；采用 [Kimball 可加、半可加、不可加分类](https://www.kimballgroup.com/data-warehouse-business-intelligence-resources/kimball-techniques/dimensional-modeling-techniques/additive-semi-additive-non-additive-fact/)判断可重聚合的维度 |
| 指标输入与输出 | 按业务口径声明输入，返回指标值以及正确解读该值所需的信息。时间字段按实际接口契约读写。 |
| 业务含义 | 从可信业务定义确定事实粒度、有效状态、统计事件、日历、单位、公式和舍入规则，按实际需要写入指标 description 与 BFF JSDoc |

Agent 自主选择符合契约的数据访问与计算方法，不要求用户选择 SQL/BFF、数值表示或建设路径。先读取云端当前定义和可信业务依据；未说明且会影响结果的业务决策，用宿主结构化提问能力（如 question）澄清，无该能力时普通对话询问。提问澄清业务目标、范围、口径或验收要求，不用行业惯例补造企业规则；开发任务涉及的必要技术约束仍按已知事实核实。已有定义、说明和实际接口相互矛盾时，指出冲突并澄清受影响部分；独立可完成部分继续，不静默改变口径或参数。

先查目标应用的业务契约、数据集事实和 SQL/BFF，再按 `rabetbase schema` 确认命令。已有入口能满足口径时复用；名称相近或返回成功不能证明口径相同。

只向用户确认仍影响结果的歧义：

| 项目 | 确认内容 |
| --- | --- |
| 统计对象与范围 | 订单、用户还是请求；去重键；支付状态、退款与冲正；总量和子集分别命名 |
| 时间 | 事件时间、入账时间或快照时点；业务时区及区间边界 |
| 单位与精度 | 次数、币种、积分或比例；金额精度、零分母及缺失值处理 |
| 输入与输出 | 已有接口允许的筛选、结果字段、完整性、错误及空值语义 |

在 BFF JSDoc 中维护真实参数、返回值与业务说明，回读生成的 contract；不手工维护指标契约副本或猜测缺失规则。时间格式按实际接口使用，不自动把日期、秒值或字符串转换为另一种格式；业务自然日使用已确认时区，不取机器本地时区。新接口明确约定边界，例如 `[startTime, endTime)`；不能用约定覆盖已有接口的真实含义。

指标名称表达稳定业务口径。区间发生量、当前存量和历史时点存量分别确认，不因查询日/月粒度复制定义，也不要求当前存量接口提供时间参数。输出按真实语义选择单值、对象或序列；对象和序列应围绕该指标，不把任意页面 VO 当作指标结果。

### 时间处理规范

新建指标 ENDPOINT 需要时间范围时，用 `startTime`、`endTime` 表示含起点、不含终点的区间。调用方按本次查询适用的日历计算边界，默认发送 UTC `Z`。BFF 接受 `Z` 或显式时区偏移，可含毫秒。先解析为时刻，再校验顺序、跨度及业务日历对齐要求。结果需要返回时刻时，用 UTC `Z` 表示，按源精度保留毫秒。

仅查询区间总量时，`startTime` 和 `endTime` 已能确定查询范围，通常无需额外传 `timeZone`。

解释“昨日”“上月”时，固定本次查询的参考时刻，按已确认的统计口径确定期间。按日、月汇总时，查询边界与分组使用同一日历。只有缺失的信息会改变结果时，才向用户确认。

数据库的秒值或日期由 BFF/SQL 按已知存储语义转换。查询截止和数据完整入账截止分别核实。

已有指标按当前生效契约传参，包括已约定的毫秒整数。迁移前盘点页面和 Skill 调用方，协调切换 BFF、声明及消费者，并针对同一业务期间对账，保留原有统计事件、结算日历、过滤、精度与空值语义。

## 2. 维护并发布应用级定义

按变更的业务含义选择验收路径。即使只改 `/description`，把「按创建日」改为「按入账日」，或把「待核实」改为「统计日次日可查（T+1）」，都属于修改口径。

| 用户任务 | 执行路径 |
| --- | --- |
| 查找与查看 | list 筛选候选，detail 读取当前定义及契约诊断 |
| 新建 | 核对 BFF → example/schema → validate → publish --dry-run → publish → detail |
| 仅改文案 | 从目标应用的 `detail` 读取已保存的定义，保留公式、范围和时效的原意。预演确认差异仅含 `/description`，发布后按指标 code 回读三行文案，一致即可完成。若 `detailError` 为 `104` 且保存态定义可读，可照此验收文案，注明生效契约未核验。 |
| 修改口径 | 改公式或范围，核对生效的 BFF/SQL，用同一期间、能区分新旧口径的样本与可信来源对账。改时效，核实目标环境从入账或批任务产出到数据可查的时间，证据不足时保留「待核实」。更新定义时先校验、预演，发布后回读。缺少证据的口径项标为未验证。 |
| 修改 BFF 契约 | 按同应用的 `target.functionName` 核对绑定指标及受影响的调用方。发布 ENDPOINT 后核对云端版本，从指标详情回读生效的输入、输出 Schema，再用 `lovrabet metric exec` 以代表性参数核验变更字段。若同时改变业务含义，一并完成对应的口径验收。 |
| 删除 | 核对使用方与退役授权 → delete --dry-run 核对精确身份 → delete --yes；成功结果已包含删除后回读确认 |

编辑前用 `detail` 核对目标应用的最新定义及契约诊断。生效契约不可读时，将依赖该契约的验收项标为未验证。

新建与修改共用 publish，按精确 code 是否存在选择创建或更新；没有独立 create/update 命令。失败恢复和删除细节见命令参考。


读取 [metric 命令参考](../references/rabetbase-metric.md)，使用 `rabetbase metric schema --kind definition` 和 `rabetbase metric example` 获取结构与示例。每项定义为单个 JSON 对象，仅 code、target 必填；description（Markdown）、unit、label、synonyms、categoryPath 可选，缺省不猜测补齐。完整详情另含派生的只读 contract。同义词只用于理解和候选发现，执行使用 code；列表关键词搜索 code/label/synonyms/description。

- 新建或迁移时，从存量页面、报表或已确认的运营用语中收集别名。核对统计对象、范围、时间和聚合方式，与当前口径一致的原词才写入 `synonyms`。没有可靠用语时省略；旧称若只适用于旧口径，留在变更说明中。发布后用原词执行 `rabetbase metric list --keyword <原词>`，核对候选中有预期的 `code`。
- 一个指标绑定同应用的 BFF functionName；不支持 SQL target、个人 BFF、跨应用或选版，BFF 内可复用已有 SQL。
- `description` 可选。撰写时固定三行 Markdown，依次为 **计算公式**、**统计范围**、**数据时效**，每行用一个换行分隔。新写或改变计算口径前，核对业务定义与 BFF、SQL。**计算公式**只写一行「业务指标名 = 业务公式」。按实际算法选运算符。逐笔求和用 `Σ（每笔业务量）`，有固定周期时写清周期和单笔对象，例如「月度模型消耗积分 = Σ（该月每次模型调用消耗的积分）」。余额用加减，去重计数写出去重对象，比率写出分子和分母。保留影响结果的运算项，用维护人员熟悉的业务名称。
- **统计范围**写「对象，时间口径」，例如「指定租户，查询时点」。只补会改变纳入范围的条件，如退款仍计入；公式已有的运算省略。空集、返回类型和精度在 BFF 契约中核验。
- 涉及日/月归期时，统计范围写清统计事件和期间，例如「按入账月，当月截至查询时刻」。用户要求或生效契约约定了特殊归期规则时，在该指标的说明和实现中落实。
- **数据时效**用一个短标签。已核实从业务事件到可查的延迟，可写「入账后实时可查」「入账后 5 分钟内可查」或「入账后 2 小时内可查」。只有调度依据时写「每小时刷新」。按日交付写明 T 对应的业务日，截止时间、工作日历按已确认的约定补充。沿目标环境生效的 BFF、SQL 追到源表，核对写入、同步或批任务产出与查询可见时间。查询时刻、查询上界和当前表直读均不足以推导上游延迟。证据不足时第三行填「待核实」。
  - 入账明细及其查询时求和、计数，已确认入账记录当日可见时写「入账当日可查（T+0）」。业务发生至入账的延迟、全日账目何时结清须另行核实。
  - 读取批处理结果时，核实任务覆盖的统计日以及结果成功产出后何时可见。确认次日可查时写「统计日次日可查（T+1）」。有多条依赖时核对所有影响结果的来源。日/月分组、聚合函数、任务启动时间都不足以单独确定时效。
- 从指标详情的只读 `contract` 读取 `inputSchema` 和 `outputSchema`，分别核对业务请求和成功返回数据。发布指标定义时省略 `contract`。需要修改参数语义、结果边界或示例时，更新绑定 ENDPOINT 的 JSDoc 声明，发布后回读指标详情。
- 云端指标的当前生效定义是事实来源；本地 JSON 可作为临时编辑文件，不要求纳入业务源码仓。业务 Skill 引用应用和指标名，在实际授权范围内复用该应用的定义，不复制契约。业务公式由 BFF 或其调用的 SQL 执行；定义不存执行代码、调用参数、凭证和结果映射。
- `bff push` 只对文件名以小写 `metric` 开头的待上传 ENDPOINT，按当前应用和完整注册名反查云端指标。仅当至少一个指标直接绑定该入口时，才检查源码的契约声明。反查失败时提示绑定未确认。无需本地指标文件，候选源码有明确声明问题时给出 warning，上传继续。首次发布 ENDPOINT 时，云端可以尚无指标。指标登记后，用 `rabetbase metric validate --code <code> --appcode <app>` 核对云端定义和生效绑定。预演可用 `bff push --dry-run` 查看相同提示。
- 用 `rabetbase metric validate --file <metric.json>` 离线校验，发布前加 `--appcode <app>` 核对生效绑定，依照[口径比对](../references/rabetbase-metric.md#口径比对)说明一致依据、冲突或证据缺口。使用 `metric publish --file <metric.json> --appcode <app> --dry-run` 预览后发布。
- 发布时使用应用内唯一的 `code`（例如 `paid_order_count`），不添加 `metrics.` 资源前缀。开发操作使用 `rabetbase metric list --keyword <关键词>` 发现指标摘要，修改前用 `rabetbase metric detail --code <code>` 读取最新定义及契约诊断。运行态用 `lovrabet metric list` 找到指标，将返回的 `code` 传给 `lovrabet metric detail --code <code>` 或 `lovrabet metric exec --code <code>`。同一指标串行维护，避免并发覆盖。

接口文档不足以确定参数或结果时先补齐可信契约，不让 Agent 根据名称猜调用方式。名称与 AppCode 定位定义，不构成服务端资源版本或历史快照。

categoryPath 为可选的主业务分类路径，按父级到子级排列，只允许1或2个非空且无首尾空白的字符串，例如 `["消费治理", "模型用量"]`；不能使用空数组、null 或三级路径。缺省表示未分类，展示方可显示“未分类”，CLI 不补默认值。该字段仅用于发现与组织，不参与标识、计算或权限，也不作为执行参数；调整分类不改变 code。分类名称由应用维护，不要求固定业务枚举。list/detail 返回分类路径；`--keyword` 对 code、label、synonyms 和 description 做字面子串匹配，categoryPath 不参与匹配。

## 3. 复用 SQL/BFF 执行

1. 基于数据集详情确认事实粒度、关联键与基数，避免一对多 JOIN 放大金额或次数；跨库按 [跨库 BFF 指南](cross-database-bff.md) 处理。
   同时核实时间字段记录的是业务发生、数据采集还是状态更新，以及历史记录是否保留。当前状态表不能直接证明完整历史发生量；数据不足时列明缺口，替代口径经确认后另行定义。
2. 将固定业务条件、去重和聚合放在 SQL/BFF，权限由平台及可信执行上下文落实。调用参数不能覆盖固定口径或身份。
   指标 ENDPOINT 拒绝查询时，按 [ENDPOINT 的业务错误](backend-function.md#endpoint-的业务错误) 区分参数错误与当前身份无权执行。
3. 按 [SQL 工作流](sql-creation-workflow.md) 或 [BFF 工作流](bff-creation-workflow.md) 维护和发布。需要统一旧接口形状时使用薄 BFF，并维护其真实参数、结果契约。
4. 用 `lovrabet metric exec --dry-run` 读取当前定义，检查参数是 JSON 对象且数值可安全传输。预演不会调用 BFF。核对目标只读、调用授权和参数含义后，再用 `lovrabet metric exec` 执行。命令成功时保留原始结果，影响读数的契约偏差通过简短提示定位。业务口径仍需对账。

指标消费者只组织查询、展示与分析。期间去重人数不能由每天去重人数相加；余额不能跨日求和；平均数和比例不能直接平均。需要新的计算口径时维护明确的 SQL/BFF，不在目录中增加通用公式或动态关联。

### 数值精度与区间聚合

BFF/SQL 及底层服务负责计算精度、业务舍入和返回表示；位于服务端不代表普通浮点运算天然精确。需要精确金额或高精度计算时，使用数据库 DECIMAL/NUMERIC 或服务端已有的精确计算能力，并保持读取、运算和序列化链路的精度。普通计数和允许近似的比例按实际精度要求使用数值类型，不统一改成字符串。

大整数和需精确传递的十进制结果按契约返回字符串，例如 `{ "amount": "123.45" }`；明确单位且在安全范围内的整数也可承载定点金额。不能先转普通浮点数再转字符串来恢复精度。contract 声明类型、单位、有效范围、精度及舍入规则；CLI 只做外层与传输完整性检查并原样透传，不承担业务计算、精度修复或单位换算。安全整数检查不保证十进制计算无损，CLI 执行成功不证明业务计算正确。

区间聚合在服务端依据正确事实粒度、过滤条件和业务规则完成，优先使用权威明细或可核验的等价汇总；不能累加页面已格式化、仅为展示而舍入、分页截断或 TopN 的值来代替总体。直接扫描明细也必须核对关联基数、去重和数据完整性，不以“原始”代替口径正确。

| 指标性质 | 聚合规则 |
| --- | --- |
| 可加指标，如同币种销售额 | 在精确运算下，对完整互斥、同口径、同数据状态且保留所需精度的中间汇总求和，与明细聚合等价；可以复用，不要求每次重扫明细 |
| 比例与均值 | 先汇总同范围的分子、分母或总量、计数，再计算；不能直接平均各行比例或均值，零分母按业务契约处理 |
| 去重计数 | 按目标期间与去重键在服务端去重；分区可能有同一对象时，分区去重数不能直接相加 |
| 余额、库存等快照 | 按目标时点与可加维度计算，不能把多个日期的快照求和当作期间余额或库存 |
| 分位数等分布统计 | 按约定算法与目标样本计算，分区 P95 不能直接平均或相加得到总体 P95；仅在算法支持、状态可合并且精度要求满足时复用中间状态 |

核实数据库的空集、NULL 与计数语义：`COUNT(*)` 统计行，`COUNT(column)` 统计非 NULL 值；无输入行时 `SUM` 通常返回 NULL、`COUNT` 返回 0。技术返回值不能单独证明业务上的“没有发生”或“数据未知”；只有企业明确约定空集为零且覆盖已确认时，才由 BFF/SQL 实施相应转换。零分母、缺失和失败分别处理，不以统一补零掩盖缺口。分位数算法、近似误差等仅在任务涉及且影响结果时确认，不要求每项指标填写统计方法问卷。

舍入时点与模式属于业务口径。仅用于展示的舍入留到展示时；已确认逐行结算舍入后再累加的规则必须保留，不能擅自替换成汇总后舍入。没有明确规则且会影响结果时，先查企业契约，再向业务负责人确认。

### 新建指标 BFF 与页面 VO

按实际复用关系选择入口：

| 已确认的情况 | 实现方式 |
| --- | --- |
| 已有 ENDPOINT 的命名、固定口径与契约均满足要求 | 直接绑定，不为改名或包一层结果新增转发接口 |
| 需要新建指标 BFF，计算只由此入口使用 | 一个指标一个独立 ENDPOINT，直接实现查询和校验 |
| 页面 VO 或其他入口需要复用同一计算 | 提取必要的 COMMON；指标 ENDPOINT 与页面 ENDPOINT 分别调用它，页面继续组装原 VO |

指标 ENDPOINT 的文件名以小写 `metric` 开头，例如 `metricOpenOrderCount.js` 或 `metricsOpenOrderCount.js`。CLI 用文件名去掉 `.js` 后的名称作为注册名。首次登记和换绑校验目标注册名；既有非标准绑定仍可读取、校验并维护口径。此类入口上传时会跳过指标预检，迁移前按指标 code 核验生效契约。调用目标以定义中的 `target` 为准，不从指标名推导函数名。

### 编写指标 ENDPOINT 契约

指标定义通过同应用的 `target.functionName` 直接绑定 ENDPOINT。这项契约要求只适用于被绑定的入口。COMMON 可复用计算和权限校验，按其真实调用方约定返回。首次登记时可先写好拟绑定入口，发布并登记后核验生效契约。

被同应用指标直接绑定的 ENDPOINT，在显式 `@inputSchema` 上一行写 `关联指标：<label>（<code>）`。名称和编码取自云端指标定义，按 `target.functionName` 核对绑定。缺少名称时只写编码；多个指标共用入口时，按编码排序，用英文逗号和空格分隔。修改输入或输出字段时，核对绑定指标的调用方。

从一次业务请求和一次成功结果开始。在导出函数前的 JSDoc 中声明两侧的 JSON Schema（Draft 2020-12）。简单输入可从 `@param` 及 `params.<字段>` 推导；需要枚举、完整示例或多字段限制时，写显式 `@inputSchema`。输入和输出分别取各自的声明。写有显式 Schema 标签时，对应的输入或输出以该标签为准。输出用 `@outputSchema` 声明完整业务对象、必返字段、数组元素及至少一个可通过校验的完整成功示例。普通 `@example` 不会填入 `outputSchema.examples`。函数直接返回业务对象，平台将它放在成功响应的 `data` 中。

用本次选定的 CLI 执行 `metric example` 读取支付订单数定义。按 `target.functionName` 查看同一 CLI 包中的 `templates/metrics/metricPaidOrderCount.js`。示例中的 `commonCountPaidOrders` 表示应用已有的共享查询；接入时使用本应用已核实的时间校验、权限和计数实现。

| 读数 | 成功业务结果与 BI 绑定 |
| --- | --- |
| 当前余额 | 声明余额的类型、单位和无记录时的含义。例如，某积分余额指标在 `aggregate.value` 中以 `"0"` 表示已知零余额，以 `null` 表示无记录。若口径为截至指定时刻的余额，且实际截止时刻可能早于请求值，返回实际截止时刻。 |
| 区间趋势 | `aggregate.granularity` 声明本次粒度，`aggregate.points` 中每个点给出 `date`、`value` 和实际 `startTime`、`endTime`。有可靠区间合计时才提供 `aggregate.value`。 |
| 汇总与明细 | 顶层入参 `currentPage`、`pageSize` 只作用于 `record.tableData`；`record.paging` 给出整数 `currentPage`、`pageSize`、`totalCount`。每页的 `aggregate` 覆盖整个查询区间，空结果仍包含空表和总笔数 0。 |

按能力选择字段。请求回显 `query` 默认省略，仅在来源确认完整入账截止时提供 `dataThrough`；实际范围可能与请求不同且无法从结果还原时提供 `effectiveRange`。需对账的十进制量在汇总、趋势、明细中使用相同的字符串表示。各层的 `required` 列出成功时保证出现的字段，可空值由类型单独表达。

### 发布依赖与部分失败恢复

先发布实际依赖的 SQL/COMMON，并回读确认源码；再发布引用它们的 ENDPOINT。需要登记或修改指标时，再单独提交指标定义。发布每项时记录应用、名称、阶段及回读结果，已核验成功的项直接跳过，只续跑缺失或不一致项；依赖未就绪时不发布其下游定义。

保存报错或超时时先按 BFF/SQL 工作流回读精确对象，定义用 metric detail 回读；当前契约不可用时查看 metric detail 的保存态与诊断；定义损坏时通过指标管理核查保存记录。内容已一致就记为已生效，不因上一次响应失败重复写入。已确认缺失且瞬时故障已恢复时可做一次受控重试；同项持续失败时停止重复请求，保留发生时间、应用、对象名、错误及 traceId，用日志定位。只保留必要诊断信息，凭证与业务数据不进入交付记录。

## 4. 验收与交付

先选择少量真实指标，例如订单数与已支付金额。用可独立核验的业务明细对账；合成样例只验证设计，不证明真实业务正确。

- 按指标业务语义选择适用的状态、去重与时间边界案例；例如订单指标覆盖支付/未支付、退款和重复明细，不将这些订单状态作为其他指标的必测条件。
- 按接口契约验证空集、零值、null/不可用及空数组的不同语义，不要求空区间一律返回零；缺失、失败、历史不全和未知不能替换为零。
- 分页、TopN 与页面当前页不改变统计总量；涉及比例时明确完整分母。
- 同一身份、业务筛选与数据状态下，页面 VO 中的对应值与指标端点结果一致；两者相等仍需权威明细对账。

`metric validate` 检查定义结构，并用 warning 报告 Schema、示例和 BI 字段的问题。显式传入 `--appcode` 可核对已发布指标的当前绑定；业务仓的测试验证真实计算和拒绝条件，目标环境验证数据、权限与查询性能。区间或返回条数上限不能替代执行计划核查。各层按职责验收，不把一种证据当作全部通过。

交付已发布的应用与指标名、真实验收证据和已知限制。口径或执行实现变化时更新定义说明及 BFF JSDoc，并回读服务端生成的 contract，重新验收，并记录真实可核验的实现修订；没有版本或快照能力时不承诺历史重放。页面交给 Agent 的是已应用的筛选，不是未提交的表单值。

### 交付与消费验证

交付云端指标所属应用、稳定指标名、适用业务对象与期间、完整契约的读取入口，以及已知限制。按当前账号分别核对开发和运行操作的认证与权限；同一用户可以使用两个 CLI，不要求因岗位更换账号，不复制 Cookie/AK，不以管理员验证代替当前账号验证。源码仓和本地定义文件可以留作开发辅助，不是消费指标的前提。

验收记录分开列出以下证据，未验证的项目明确标记未验证：

| 证据 | 说明 |
| --- | --- |
| 定义合法 | validate 验证开发定义外层结构 |
| 发布回读 | 核对云端定义和绑定；在同一 ENDPOINT 版本生效期间，分别比对 BFF 元数据与指标详情中两份 Schema 的 JSON 值。无法关联发布记录时仅确认内容相同 |
| 运行结果 | lovrabet 在实际应用下完成调用；另行核对实际参数与返回结果 |
| 业务对账 | 实际结果与可信业务明细或既有权威口径一致 |
| 受限角色验证 | 记录实际执行主体、应用、授权范围及允许/拒绝操作，不记录凭证 |

未知业务口径请业务负责人确认，计算能力缺口按明确的开发任务处理；权限拒绝返回受阻操作、原错误及已知权限要求，再次执行前重新核验；工具或运行能力不足保留复现条件和实际错误。交付不自动授权订阅创建、对外投递或权限修改，按用户已确认的对象与范围继续。
